# Крестики-нолики — Frontend

Современный frontend на React + TypeScript + Vite для игры «Крестики-нолики» с системой аутентификации, профилями пользователей и ИИ-противником.

## 🚀 Возможности

- **Система аутентификации**: Регистрация, вход и управление базовой аутентификацией через AuthContext
- **Профили пользователей**: Просмотр статистики игрока и информации об аккаунте
- **Динамический размер поля**: Поддержка игровых полей любого размера (не только 3x3)
- **Обновления в реальном времени**: Мгновенная обратная связь при ходах с индикаторами загрузки
- **Обработка ошибок**: Надёжная обработка ошибок с автоматическими повторными попытками
- **Адаптивный дизайн**: Красивый тёмный интерфейс с плавными анимациями
- **Типизация**: Полная поддержка TypeScript для отсутствия ошибок времени выполнения
- **Пользовательские хуки**: Игровая логика инкапсулирована в хук `useGame` для повторного использования

## 📋 Начало работы

- Node.js 18+

Чтобы развернуть frontend в production environment, вам нужно собрать приложение с помощью `npm run build` и обслуживать статические ресурсы с помощью веб-сервера, такого как Nginx или Apache. Вы также можете настроить Content Delivery Network (CDN), чтобы улучшить производительность и уменьшить задержку для пользователей по всему миру.

## 🎮 Как это работает

### Процесс аутентификации

1. **Регистрация**: Новые пользователи создают аккаунт через RegisterForm
2. **Вход**: Существующие пользователи аутентифицируются через LoginForm
3. **Отправка учётных данных**: Учётные данные отправляются с каждым запросом
4. **Доступ к профилю**: Аутентифицированные пользователи могут просматривать свой профиль

### Игровой процесс

1. **Инициализация**: После входа хук `useGame` подключается к backend и начинает новую игру
2. **Ход игрока**: Нажмите на пустую клетку, чтобы сделать ход (X)
3. **Ответ ИИ**: Backend обрабатывает ход и возвращает ход ИИ (O)
4. **Победа/Ничья**: Игра заканчивается при победе одного из игроков или заполнении поля

### Возможности подробно

- **Повторные попытки**: Неудачные запросы автоматически повторяются до 3 раз с задержкой в 1 секунду
- **Валидация данных**: Все ответы от сервера проверяются перед использованием
- **Состояния загрузки**: Поле блокируется во время обработки хода для предотвращения дублирования
- **Отображение ошибок**: Ошибки подключения отображаются пользователю с понятными сообщениями
- **Auth Context**: Централизованное управление состоянием аутентификации во всех компонентах

## 🔧 Конфигурация

### Прокси Vite

Файл `vite.config.ts` проксирует запросы `/game` к Java-backend:

```typescript
server: {
  proxy: {
    '/game': {
      target: 'http://localhost:8080',
      changeOrigin: true,
    }
  }
}
```

### API эндпоинты backend

#### Аутентификация

- `POST /auth/signup` — Регистрация нового пользователя
- `POST /auth/login` — Вход и получение сессии

#### Пользователь

- `GET /user/profile` — Получить профиль текущего пользователя

#### Игра

- `POST /game` — Начать новую игру
- `POST /game/:id` — Сделать ход для игры с указанным ID
- `GET /game/:id` — Получить статус игры

Ожидаемый формат ответа игры:

```json
{
  "id": "uuid",
  "gameMap": {
    "map": [[0, 1, 2], ...],
    "size": 3
  },
  "status": "PLAYING|CROSS_WIN|ZERO_WIN|DRAW"
}
```

## 🐛 Устранение неполадок

### Сообщение "Connection Error"

- Убедитесь, что Java-backend запущен на `http://localhost:8080`
- Проверьте доступность эндпоинтов `/game` и `/auth`
- Смотрите консоль DevTools браузера для подробных сообщений об ошибках

### Проблемы с аутентификацией

- Убедитесь, что Spring Security на backend настроен правильно
- Проверьте настройки CORS в SecurityConfig
- Убедитесь, что учётные данные Basic Auth отправляются в заголовке Authorization

### Поле не загружается

- Проверьте, что backend возвращает корректную структуру данных игры
- Проверьте настройки прокси в `vite.config.ts`
