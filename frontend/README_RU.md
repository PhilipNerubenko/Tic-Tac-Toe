# Крестики-нолики — Frontend

Современный фронтенд на React + TypeScript + Vite для игры «Крестики-нолики» с JWT-аутентификацией, профилями пользователей, историей игр, таблицей лидеров и ИИ-противником.

## 🚀 Возможности

-   **JWT Аутентификация** — Безопасный вход/регистрация с Bearer токенами и автоматическим обновлением
-   **Профили пользователей** — Статистика игрока и информация об аккаунте
-   **Динамический размер поля** — Поддержка игровых полей любого размера (не только 3x3)
-   **Обновления в реальном времени** — Мгновенная обратная связь при ходах с polling и индикаторами загрузки
-   **Обработка ошибок** — Надёжная обработка ошибок с автоматическими повторными попытками (3 попытки, 1с задержка)
-   **Адаптивный дизайн** — Красивый тёмный интерфейс с плавными анимациями
-   **Типизация** — Полная поддержка TypeScript для отсутствия ошибок времени выполнения
-   **Пользовательские хуки** — Игровая логика инкапсулирована в хук `useGame` для повторного использования
-   **PvP Мультиплеер** — Присоединяйтесь к активным играм и играйте против других пользователей
-   **Таблица лидеров и история** — Просмотр топ-игроков и вашей истории игр

## 🎮 Как это работает

### Процесс аутентификации (JWT)

1.  **Регистрация**: Новые пользователи создают аккаунт через `POST /auth/signup`. Backend возвращает `accessToken` и `refreshToken`, которые сохраняются в `localStorage`. Затем фронтенд запрашивает профиль через `/auth/me`.
2.  **Вход**: Существующие пользователи аутентифицируются через `POST /auth/signin` с логином/паролем. Та же обработка токенов.
3.  **Хранение токенов**: Токены хранятся в `localStorage` под ключами `ACCESS_TOKEN_KEY`, `REFRESH_TOKEN_KEY`, `USER_DATA_KEY`. Access-токен отправляется в заголовке `Authorization: Bearer <token>` с каждым запросом через `authorizedFetch`.
4.  **Автоматическое обновление**: При получении 401 от API, `authorizedFetch` автоматически вызывает `POST /auth/refresh/access` с refresh-токеном для получения новых токенов и повторяет исходный запрос.
5.  **Доступ к профилю**: Аутентифицированные пользователи могут просматривать свой профиль (userId, login) с `/auth/me`.

### Игровой процесс

1.  **Инициализация**: После входа хук `useGame` подключается к backend и начинает новую игру (`POST /game?size=3&vsAi=true`).
2.  **Ход игрока**: Нажмите на пустую клетку, чтобы сделать ход (X). Поле блокируется во время обработки хода.
3.  **Ответ ИИ**: Backend обрабатывает ход и возвращает ход ИИ (O) автоматически в том же ответе.
4.  **Победа/Ничья**: Игра заканчивается при победе одного из игроков или заполнении поля. Статус становится `CROSS_WIN`, `ZERO_WIN`, или `DRAW`.
5.  **Polling**: Состояние игры опрашивается каждые 2.5 секунды для обнаружения ходов соперника в PvP или завершения игры.
6.  **Проверка соперника**: Во время хода соперника в PvP, автоматическая проверка на покинул ли соперник игру (`/game/{id}/check-opponent-left`) при каждом опросе.

### Возможности подробно

-   **Повторные попытки**: Неудачные запросы автоматически повторяются до 3 раз с задержкой 1 секунда.
-   **Валидация данных**: Все ответы от сервера проверяются перед использованием (`isValidGameData` type guard).
-   **Состояния загрузки**: Поле блокируется во время обработки хода для предотвращения дублирования.
-   **Отображение ошибок**: Ошибки подключения и 403 (не ваш ход) показываются пользователю с понятными сообщениями.
-   **Auth Context**: Централизованное управление состоянием аутентификации во всех компонентах с сохранением токенов.
-   **PvP поддержка**: Создайте игру с `vsAi=false`, поделитесь ID сессии с другом, он присоединяется через `POST /game/{id}/join?guestId=<uuid>`.
-   **Статистика**: Просмотр истории игр (`/game/history`) и глобальной таблицы лидеров (`/game/leaderboard?n=10`).

## 🔧 Конфигурация

### Прокси Vite

`vite.config.ts` проксирует API запросы на Java backend. Это избегает CORS проблем в разработке:

```typescript
server: {
  proxy: {
    '/game': {
      target: 'http://localhost:8081',
      changeOrigin: true,
    },
    '/auth': {
      target: 'http://localhost:8081',
      changeOrigin: true,
    },
  },
}
```

**Важно:** Цель прокси должна соответствовать порту вашего backend. По умолчанию `8081`. Измените, если backend работает на другом порту.

### API эндпоинты backend

#### Аутентификация

-   `POST /auth/signup` — Регистрация нового пользователя (возвращает JWT токены)
-   `POST /auth/signin` — Вход с учётными данными (возвращает JWT токены)
-   `POST /auth/refresh/access` — Обновить access-токен с помощью refresh-токена
-   `POST /auth/refresh/refresh` — Ротация refresh-токена
-   `GET /auth/me` — Получить профиль текущего пользователя (требует Bearer токен)
-   `GET /auth/{id}` — Получить пользователя по ID (self или admin only)

#### Пользователь

-   `GET /auth/me` — Получить профиль текущего пользователя (заменяет старый `/user/profile`)

#### Игра

-   `POST /game?size=3&vsAi=true` — Начать новую игру (против ИИ или PvP)
-   `POST /game/:id/move` — Отправить ход для игры с указанным ID (тело: `{ "gameMap": { "map": [...], "size": 3 } }`)
-   `GET /game/:id` — Получить статус игры
-   `GET /game/active` — Список всех доступных (ожидающих) игр для PvP присоединения
-   `POST /game/:id/join?guestId=<uuid>` — Присоединиться к существующей игре как второй игрок
-   `POST /game/:id/check-opponent-left?timeoutSeconds=30` — Проверить, покинул ли соперник игру
-   `GET /game/history` — Получить все завершённые игры текущего пользователя
-   `GET /game/leaderboard?n=10` — Получить топ N игроков по проценту побед

**Ожидаемый формат ответа игры:**

```json
{
  "id": "uuid",
  "gameMap": {
    "map": [[0, 1, 2], [0, 0, 0], [0, 0, 0]],
    "size": 3
  },
  "status": "PLAYING|CROSS_WIN|ZERO_WIN|DRAW|WAITING_FOR_PLAYERS|OPPONENT_LEFT",
  "playerX": "uuid",
  "playerO": "uuid|null",
  "currentPlayer": "uuid",
  "winner": "uuid|null",
  "lastActiveAt": "2025-01-15T10:30:00Z",
  "createdAt": "2025-01-15T10:25:00Z"
}
```

**Значения ячеек:**
-   `0` = EMPTY
-   `1` = CROSS (игрок X)
-   `2` = ZERO (игрок O или ИИ)

## 🐛 Устранение неполадок

### Сообщение "Connection Error"

-   Убедитесь, что Java backend запущен на `http://localhost:8081` (не 8080!)
-   Проверьте доступность эндпоинтов `/game` и `/auth` через браузер или curl
-   Проверьте, что конфигурация proxy в `vite.config.ts` соответствует URL backend
-   Смотрите консоль DevTools браузера на наличие подробных сообщений об ошибках и сетевые ошибки во вкладке Network

### Проблемы с аутентификацией

-   Проверьте правильность учётных данных; повторная регистрация может вернуть 409 conflict
-   Убедитесь, что токены хранятся в `localStorage` с правильными ключами (`accessToken`, `refreshToken`)
-   Проверьте, что `authorizedFetch` включает заголовок `Authorization: Bearer <token>` (Network tab)
-   Если 401 сохраняется после обновления, возможно, вы вышли — войдите снова
-   Очистите `localStorage` и пройдите аутентификацию заново, если структура токена повреждена

### Поле не загружается

-   Проверьте, что backend возвращает корректную структуру данных игры с полями `id`, `gameMap`, `status`
-   Проверьте настройки прокси в `vite.config.ts` — должен указывать на правильный порт (`8081`)
-   Убедитесь, что вы аутентифицированы; неаутентифицированные запросы к `/game/*` возвращают 401
-   Проверьте консоль на ошибки `Failed to fetch` или CORS (прокси должен предотвращать CORS)

### 403 Forbidden (Не ваш ход)

Возникает когда:
- Вы пытаетесь присоединиться к игре, которую не создавали или к которой нет доступа
- Вы пытаетесь сделать ход, когда не ваш ход (статус не `PLAYER_TURN` или `currentPlayer !== yourId`)
- Вы пытаетесь получить доступ к игре другого пользователя (backend проверяет принадлежность)

Ждите своего хода или создайте/присоединитесь к правильной игре.

### Проблемы с портами

Распространённые проблемы:
- Backend работает на **8081** (внешний), **8080** (внутренний Docker)
- Frontend dev работает на **5173**
- Если видите "ECONNREFUSED 8080", ваш proxy может указывать не на тот порт — обновите `vite.config.ts` на `8081`

## Production-развертывание

Для развёртывания фронтенда в production:

1.  **Настройте окружение** — Убедитесь, что URL backend API задан правильно. Для production обновите Vite proxy или замените API вызовы на абсолютные URL вашего развёрнутого backend.
2.  **Сборка приложения:**

    ```bash
    npm run build
    ```

    Результат в папке `dist/` (статичные файлы).

3.  **Обслуживание веб-сервером** — Используйте Nginx, Apache или CDN:

    **Пример Nginx:**
    ```nginx
    server {
        listen 80;
        server_name your-domain.com;
        root /path/to/tic-tac-toe/frontend/dist;
        index index.html;

        location / {
            try_files $uri $uri/ /index.html;
        }

        location /api/ {
            proxy_pass http://localhost:8081;  # Backend
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }
    }
    ```

4.  **Установите переменные окружения** для базового URL API при необходимости. Рассмотрите замену жёстко заданного proxy на URL API на основе environment через Vite `import.meta.env`.

5.  **Включите HTTPS** — Настройте SSL сертификаты в вашем reverse proxy.

### Docker (Production Frontend)

Предоставленный `frontend/Dockerfile` использует Nginx для обслуживания статических файлов. Сборка и запуск:

```bash
docker build -t tic-tac-toe-frontend:latest -f frontend/Dockerfile .
docker run -p 80:80 -e BACKEND_HOST=backend-api tic-tac-toe-frontend:latest
```

При использовании Docker Compose контейнер фронтенда использует Nginx шаблон (`nginx.conf.template`) для маршрутизации `/api/*` на backend.

## Архитектурные заметки

### Управление состоянием

-   **AuthContext** — Глобальное состояние аутентификации (пользователь, токен, функции входа/выхода)
-   **Хук useGame** — Локальное состояние игры (доска, загрузка, ошибки) с сайд-эффектами (polling, повторные попытки)
-   **localStorage** — Персистентное хранение токенов между перезагрузками страницы

### Сетевой слой

-   `authorizedFetch` — обёртка вокруг `fetch` — добавляет Bearer токен, автоматически обрабатывает 401 обновление, ставит в очередь одновременные запросы во время обновления
-   Логика повторных попыток в `useGame` — до 3 попыток с экспоненциальной задержкой (фиксированная 1с)
-   Интервал polling — 2.5 секунды для обновления состояния игры

### Структура компонентов

-   **App.tsx** — Верхнеуровневая маршрутизация и глобальный layout
-   **LoginForm / RegisterForm** — Контролируемые формы с валидацией
-   **GameModeSelection** — Выбор размера доски и режима (ИИ / PvP)
-   **UserProfile** — Отображение информации о пользователе; переход к истории/лидерам
